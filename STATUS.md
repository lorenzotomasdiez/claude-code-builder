# Status

Every workflow in this library passes anatomy validation (`node scripts/validate-workflow.mjs --all`) - the required files exist, schemas are wired, every referenced agent resolves.
That is necessary, not sufficient: anatomy-clean and "actually verified to work end to end" are different claims, and this repo does not blur them.

Each package's own README carries the full, honest smoke-test record - what was run, what the input was, what passed, and what is still unproven.
This file is the index: one line per package, generated by reading every one of those READMEs, so the state of the whole library is visible without opening 30 files.

Three statuses, defined the way an engineer actually means them:

- **Solid** - a real end-to-end smoke test is recorded, and the README does not flag any open, unresolved issue since that run.
- **Needs review** - there is a real, named caveat: a fix landed after the last real run and has not been re-verified, a known issue was found and is still open, or the smoke test itself surfaced something unresolved (a round-cap reached with issues still open, a factual error the critic caught but the round cap didn't leave time to fix, and so on).
- **Never verified** - no real end-to-end run has happened yet. Only mechanical wiring is proven: syntax, anatomy, schema shapes, agent resolution. Most of these READMEs end with an explicit ask for whoever picks the package up next to run it once and record the result.

Nothing here is hidden or rounded up. A workflow with real, working orchestration and one unverified fix is marked "needs review," not "solid" - the caveat is the point.

## Reading this honestly

Roughly 40% of the library has never been run for real.
That is not an oversight being hidden - it is what an actively-built library looks like before every package gets its one real smoke test, and several of the "never verified" entries say so explicitly, with a named reason (needs a live browser, needs a real repo to push branches against, needs a working directory constraint respected) rather than "didn't get to it."

The 8-workflow greenfield pipeline (`prd-generator-v2` -> `tech-stack-selector` -> `architecture-designer` -> `design-system-foundation-v2` -> `task-breakdown` -> `tdd-blueprint` -> `feature-implementer` -> `qa-suite-pro`, see the root `README.md`) is itself split across all three states: `prd-generator-v2`/`tech-stack-selector`/`architecture-designer`/`tdd-blueprint`/`feature-implementer` are needs-review, `design-system-foundation-v2`/`task-breakdown`/`qa-suite-pro` are never-verified. It is the most actively-maintained corner of the repo - the antibloat and hub-and-spoke fixes documented in `reports/context-bloat-forensics/` all landed there first - which is exactly why it currently has the most open "not yet re-verified since the last fix" caveats. Active work in progress reads as more caveats, not fewer; a package nobody has touched in months looks artificially cleaner.
