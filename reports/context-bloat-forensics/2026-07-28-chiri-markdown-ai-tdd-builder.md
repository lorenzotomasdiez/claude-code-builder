## Narrative

The audited folder holds exactly one workflow run: `wf_805e8072-280`, a single end-to-end invocation of the `tdd-developer` skill against the `chiri-markdown-ai` repo, targeting feature **FR-8: Model selector**. 44 journal records and 17 agent transcripts (plus 17 metadata sidecars that contain nothing but `agentType`/`spawnDepth`/`model` and yield no findings) cover the whole run. Full journal at `/Users/lorenzotomasdiez/.claude/projects/-Users-lorenzotomasdiez-projects-chiri-markdown-ai/a05a0929-3d11-432d-aab3-fd64ca8fa20b/subagents/workflows/wf_805e8072-280/journal.jsonl`.

**Phase 1 - Framing (`tdd-dev-framer`, opus, agent-a1ed067144d681546).** Read the 16.6 KB FR-8 test plan `docs/tests/chiri/fr-8.md`, then oriented itself by `cat -n`-ing eight source files (~27.8 KB) and four e2e files (~15.2 KB). Ran `npm test` (green: 15 tests) and `npx playwright test --project=chromium` (red baseline: 6 failed / 26 passed). Two Bash calls died on a bare `echo ====` separator (`(eval):1: === not found`), silently dropping `docs/tech/chiri/testing.md` from context; it was never re-read. Emitted an ~18 KB structured plan: 11 scenarios, an implementation brief, 7 assumptions, 2 blockers. Plan-only run, ~48k tokens.

**Phase 2 - Test authoring fan-out (8x `tdd-dev-test-writer`, haiku).** Eight writers ran in parallel, one scenario each. Every one received the same ~5.6 KB prompt containing the full multi-gap FR-8 implementation brief plus pointers to *both* a Vitest and a Playwright convention exemplar, regardless of which kind of test it was assigned. All eight read both exemplars. Two (`a2cbb1aa`, `a5118cb2`) additionally pulled the entire 48 KB `docs/tech/chiri/index.md` blueprint in a single unlimited Read - `a2cbb1aa` quadrupled its context to ~49.5k tokens to produce a 40-line test file, and also re-read the full 12-scenario `fr-8.md` plan whose relevant scenario was already inlined in its prompt. Four agents issued `Read` on a directory and got EISDIR. Four re-read files they had just written despite the Write result explicitly saying not to. All eight wrote their file and passed StructuredOutput on the first try; none ran a test.

**Phase 3 - RED verification (`tdd-dev-verifier`, haiku, agent-a27f1119ac9f15e3f).** Ignored the supplied aggregate `npm test` command and ran eight separate per-file invocations, then read four spec files in full to map results to scenario IDs, then re-ran one suite through `grep` to re-extract an AssertionError it already had. Reported 2 passed (both flagged suspect-hollow), 3 failed, 3 errored - but reported `command: "npm test"` with `exitCode: 1`, a command never actually executed.

**Phase 4 - Implementation (`tdd-dev-implementer`, sonnet, agent-aa92ae02dbe2b9e5b).** Received a ~13 KB brief whose `<failing_tests>` array restated each of 8 on-disk test files in paragraph prose (one entry even contained a self-correcting drafting artifact); the agent then read most of those same files verbatim anyway. Created `src/core/prompt.ts`, edited `models.ts`, `schedule.ts`, `store.ts` (35 insertions, 7 deletions). Wrote a throwaway Playwright probe into the scratchpad, hit "No tests found" because it was outside `testDir`, copied it into the repo, ran it, deleted the repo copy - leaving the scratchpad copy orphaned. Ended with 19/20 vitest passing and correct written diagnoses of all three remaining failures in its own notes.

**Phase 5 - Re-verification (`tdd-dev-verifier`, haiku, agent-a3ac27a94952dd967).** Confirmed 5 pass / 3 fail. Because the prescribed `npx vitest run {file}` uses the default reporter (counts only, no test names), it had to read five full unit test files back into context purely to map passes to scenario IDs. Also re-ran an already-green e2e spec redirecting to `/tmp/test_output.txt`, a file nothing ever reads.

**Phase 6 - Adjudication (3x `tdd-dev-adjudicator`, sonnet).** Three agents independently re-derived the exact three diagnoses the implementer had already written down in Phase 4: the substring collision (`openai/gpt-4o-mini` contains `openai/gpt-4o`), `addInitScript` re-running on `page.reload()`, and `seed.ts` clobbering the persisted model. All three returned `test_wrong`. `ad03b9c5` also had its first StructuredOutput rejected for a missing required `id`, forcing a verbatim regeneration of an ~1,100-token verdict, and had to hunt down the real implementation files because the prompt's `<implementation_files>` list named four files (`prompt.ts`, `models.ts`, `schedule.ts`, `store.ts`) none of which contained the logic under test.

**Phase 7 - Test repair (3x `tdd-dev-test-writer`, sonnet).** Each rewrote its assigned spec, again carrying the full implementation brief for what were 1-4 line fixes. `ab666478` thrashed two Edits on the same block for one decision, then re-read the file it had just edited. `a6864da1` was told by its verdict to fix `e2e/seed.ts` but scoped by its `<rewrite>` block to a single spec file, so it shipped a workaround and smuggled a self-reported deviation into the free-text `asserts` field.

**Phase 8 - GREEN verification (`tdd-dev-verifier`, haiku, agent-a28917a732f1c51e9).** Clean run: two batched commands, `--reporter=verbose`, 8/8 passing, exit 0. No findings - this is the shape the earlier verifier runs should have had.

**Phase 9 - Browser journey (`tdd-dev-e2e-author` opus, then `tdd-dev-browser-runner` haiku).** The author produced a 12-step journey spec. The runner received it as a ~9.7 KB inline prompt (including a ~700-word `expectedRisk` essay it could not act on), ran `which playwright-cli`, got exit 1, and returned `blocked` with 0/12 steps after two tool calls. `docs/proof/fr-8` was left as an empty artifact directory.

**Phase 10 - Reporting (`tdd-dev-reporter`, sonnet).** Wrote the run report with no tool calls at all. Its input payload was internally contradictory (T-FR-8-2/6/10 listed in both `passed` and as `test_wrong` verdicts; `notWritten: []` alongside `droppedByCap: [T-FR-8-9, T-FR-8-11, T-FR-8-12]`), so it invented a reconciliation narrative. Final state: 8 of 11 planned scenarios written and passing, 3 dropped by the attempt cap and never written, 2 flagged suspect-hollow, browser journey blocked.

## Recommendations for the workflow library

### `tdd-developer` orchestration script (the workflow `.js`) - highest leverage

- **Stop pasting the shared brief into every fan-out agent** (finding 1, 10 recurrences). Write the implementation brief to a file once in the framing phase; pass each downstream agent only its `<test>`/`<rewrite>`/`<adjudicator_verdict>` block plus a path + line-range pointer. This is the single largest cost in the run: 8-11 KB of identical prompt per agent across 10+ spawns.
- **Decompose the framer's output** (finding 9). Have it emit one file per scenario plus one shared constraints file, and pass paths, not the whole plan object.
- **Cap the fan-out at plan time** (finding 15). Pass the attempt cap into the framer prompt so it never plans scenarios the workflow cannot execute.
- **Gate adjudication on unexplained failures only** (finding 1). The implementer's notes already contained all three diagnoses; three sonnet adjudicators re-derived them from scratch.
- **Add a `which playwright-cli` + dev-server preflight before the journey-author and browser-runner steps** (finding 7), and skip both when it fails.
- **Derive `<implementation_files>` from the failing test's testids and imports** (finding 10) rather than a fixed per-requirement list.
- **Route out-of-scope verdicts to a separate shared-fixture task** (finding 11) instead of handing a scoped agent a verdict it cannot act on.
- **Truncate failure payloads in the verifier -> adjudicator -> reporter handoff** to the assertion line plus `file:line` (finding 8).
- **Make the reporter's run payload schema mutually exclusive** - one `status` per scenario ID with optional `verdictHistory` (finding 21).
- **Make the convention-exemplar pointer conditional on `output_path`** (finding 3): Vitest exemplar for `src/core/**/*.test.ts`, Playwright exemplar for `e2e/**`. Saves ~2.5k tokens per unit-test writer.

### `.claude/agents/tdd-dev-test-writer.md`

Add to the "what you do not do" section:
- Do not Read a file you just wrote or edited; the Write/Edit result confirms success (finding 5, 6 occurrences).
- Use Glob/LS for directory listings; Read takes file paths only (finding 6, 5 occurrences).
- Do not read whole design docs; read only the line ranges referenced in your prompt (finding 2).
- The inlined `<test>` block is the sole source of truth for your scenario - do not re-read the full test plan (finding 1).
- Read only the named convention exemplar and the module under test; no repo-wide discovery greps (finding 18).
- Decide on one remedy in thinking before issuing any Edit (finding 20).

### `.claude/agents/tdd-dev-verifier.md` and the verifier prompt template

- Prescribe `npx vitest run --reporter=verbose {file}` so scenario titles appear in the output and no test files need to be read back (finding 4). Five full-file reads per verification attempt disappear.
- Append `; echo "EXIT:$?"` to the prescribed single-file command so a confirmation re-run is never needed and no `/tmp` scratch file is created (findings 16, 17).
- Run the aggregate command once first; fall back to per-file runs only for ambiguous results (finding 16).
- Require `command`/`exitCode` in StructuredOutput to come from a command actually executed in the transcript (finding 4).
- Build `failures[]` from output already in context; never re-run a test to re-extract a message you already have (finding 16).
- Phase 8 (`agent-a28917a732f1c51e9.jsonl`) is the reference shape: two batched commands, verbose reporter, no file reads, clean structured output.

### `.claude/agents/tdd-dev-adjudicator.md` and its output schema

- Drop `id` from the required schema and have the workflow attach the `<scenario_id>` it already passes in - or state the requirement explicitly in the prompt (finding 12). One rejected call cost a verbatim 1,119-token regeneration.
- Scope greps with `path:` or use `files_with_matches` before content mode (finding 18).
- Cite `file:line` rather than restating traces already present in the verification result (finding 8).

### `.claude/agents/tdd-dev-framer.md`

- Forbid bare `echo ====` separators in composed Bash commands; quote them or use `printf`, or split into one Read per file (finding 13).
- Treat any `is_error=true` Bash result as untrusted and re-issue the missing read before committing the plan (finding 14).
- Orient by grep on tag-relevant symbols plus line-ranged reads, not `cat -n` on every candidate file (finding 2).

### `.claude/agents/tdd-dev-implementer.md`

- Write throwaway Playwright probes directly under the configured `testDir` and delete them in the same Bash command; skip the scratchpad hop, since Playwright only collects specs inside `testDir` (finding 17).
- The `<failing_tests>` array should carry `{id, absolute path, one-line intent, targets}` only - drop the prose `behavior` paragraphs, which the agent bypassed in favour of reading the real files anyway (finding 1). Removes roughly two thirds of a 13 KB brief.

### `.claude/agents/tdd-dev-browser-runner.md`

- Pass the journey spec as a file path plus a steps-only excerpt; drop `expectedRisk` from the runner's prompt entirely - it belongs to the author/reviewer, not the executor (finding 7). The runner paid 9,678 tokens to produce 549.
- Create `docs/proof/<feature>` lazily after the first successful screenshot so blocked runs leave no empty directory (finding 17).
